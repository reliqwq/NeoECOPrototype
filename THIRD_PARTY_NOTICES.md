Development JARs are resolved from local files, so a fresh clone cannot compile until they are placed; the build then stops with the exact missing paths instead of failing later as unresolved symbols. The `21.2.15` release of Neo ECO AE Extension used as the baseline is published upstream (GitHub release and Modrinth); it stays a local file here - a packaging note, not a stability one.

Data Energistics is in that table because it is the only AGPL upstream we compile against, and the link is deliberately narrow. Measured on `neoecoprototype-1.4.10.jar`: exactly **one** shipped class names `com/fish_dan_` - `integration/dataenergistics/MusicDataEnergisticsPlugin`, which implements DE's published `api.entrypoint.DataEnergisticsPlugin` and registers one AE key type through `api.registry.digitalsupply`. Every DE reference in it sits inside DE's own `api/` packages; no `common/**` internal is named by anything we distribute, and the jar contains **0 entries under the `data_energistics` namespace and 0 dependency JARs**. The one shipped data file that mentions a `data_energistics:` id - `data/neoecoprototype/recipe/data_reassembler/data_flow_from_music_data.json` - is our own recipe naming their item id, which is interop rather than reuse of their files, and their resource license (separate from the code license, and All Rights Reserved) is the reason that distinction is written down. The gametest probe at `src/main/java/cn/dancingsnow/neoecoprototype/gametest/DataEnergisticsTestProbe.java` does import `common/**` types, and is therefore kept out of the release artifact (measured: 0 `gametest` classes in the jar above).

The reason this is recorded instead of assumed: implementing an extension interface from our own source does not make our jar a derivative work of theirs, but lifting their code into `src/` would, and then the whole artifact would have to be conveyed under AGPL-3.0-or-later with its section 13 remote-service terms - which our `GPL-3.0-only` declaration cannot carry. That is the line route D of the wireless channel work stays behind: its `6 x 32` port arithmetic is derived from AE2's own public constants (a dense cable is 32, a cube has 6 faces) and written here from scratch; DE's implementation was read off its bytecode for shape, the same way eco's and AE2's are, and nothing of it was copied. See docs/wireless-channel-ceiling.md.

The upstream mod's own metadata lists its authors as DancingSnow, ZhuRuoLing and Yang120231. Special thanks to `Yang120` for substantial help from the original Neo ECO AE Extension team.

One model, not a texture, is copied rather than referenced: `models/block/simplify_casing.json` carries the 13-element geometry of upstream `assets/neoecoae/models/block/casing_base.json` with its own texture slots. It is inlined on purpose - this addon's CI rejects any asset that points into the `neoecoae` namespace, because an upstream rename would otherwise turn our casing into a silent missing model. Geometry only; the surface artwork is our own.
